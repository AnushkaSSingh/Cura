# Cura Customer Support Policies

## 1. Duplicate Payment

If a customer reports being charged twice:

1. Check the customer's payment records.
2. Compare the order ID and payment amount.
3. If matching duplicate charges are verified, a refund may be initiated automatically.
4. If the duplicate charge cannot be verified, escalate the case to a human agent.

## 2. Delayed Orders

If an order is delayed:

1. Retrieve the customer's latest order.
2. Check the current order status.
3. Compare the expected delivery date with the current status.
4. Provide the customer with the verified delivery information.
5. If additional intervention is required, escalate the case.

## 3. Unknown or Unsupported Issues

If Cura cannot confidently identify or investigate the customer's issue:

1. Do not invent an answer.
2. Do not claim that an action was completed.
3. Escalate the case to a human support agent.
4. Include the original customer message and all available investigation results.

## 4. Human Escalation

When a case is escalated, the human agent should receive:

- Customer ID
- Original customer message
- Detected intent
- Relevant order information
- Relevant payment information
- Investigation findings
- Actions already taken
- Reason for escalation
- Recommended next step

## 5. Customer Context

Cura should use available conversation history when investigating a support request.

Customers should not be required to repeatedly provide information that is already available in their support history.

## 6. Safe Automation

Cura may automatically perform an action only when:

- The relevant information has been verified.
- The action is permitted by support policy.
- The system has sufficient confidence in the investigation.

Otherwise, the case should be escalated for human review.
